Reasoning effort

What the effort bar changes

Official model guide ↗

Higher effort gives the selected model more room for planning, analysis, and checking. It often takes longer and may generate more output tokens, so a task may use more credits. The model's rate per token stays the same.

Light / LowQuick, well-scoped work
MediumBalanced depth and speed
High / Extra HighMore difficult multi-step work
MaxMore time for one hard task
UltraUses subagents for separable work; usage can rise

OpenAI suggests starting with Astra Light, Sol Medium, or Luna High. Effort levels do not map exactly between model generations, and there is no fixed cost or time multiplier for each step.

Worth knowing

Price versus plan usage

The rates above estimate credit use from local token counts. Your 5-hour and weekly plan meters also depend on model, context, reasoning, tools, caching, and other activity. A lower token rate does not guarantee that every prompt uses less of your plan.

GPT‑5.6 Sol, Terra, and Luna remain available during the GPT‑6 rollout. OpenAI has not published a Terra retirement date. GPT‑5.5 retires from ChatGPT and Codex on October 14, 2026.

Interpretation and choice

What should you use?

More iterations per prompt are visible: In this all-history snapshot, 33.0% of GPT‑6 prompts made 10+ model calls versus 20.6% of GPT‑5.6 prompts. The 75th-percentile GPT‑6 prompt also had more calls, tools, and cumulative input. Reprocessing cached context across calls can make an individual response token-heavy.

But estimated credits were not higher overall: The median and 75th-percentile GPT‑6 prompt used fewer estimated credits in this sample, including within the 10+ call band. The cohorts have different work and effort settings, so neither result proves an intrinsic model advantage.

Time is not the demonstrated cause: The usable timing subset does not show a longer typical GPT‑6 response. A response that runs longer may use more tokens when it makes additional model calls, but wall-clock time itself is not charged as tokens.

Practical choice: If you want a bounded response, specify the scope and stopping point. For deeper work, extra iterations may be useful; check each prompt's elapsed time, model-call count, and cached input in Task / Session. This sample cannot establish which model produces better work for your prompts.
